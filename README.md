# 🤖 Copilot Actions Hub

A GitHub Copilot Actions hub for dispatching report-writing, presentation-generation, and agent-guided automation workflows with optional MCP-powered tool access.

## ✨ Features

- **4 workflow variations** covering unified dispatch, report writing, PPT generation, and environment bootstrap
- **7 custom agents** for AI, backend, frontend, product, security, architecture, and review-focused work
- **Skill definitions** that let workflows route tasks through reusable playbooks
- **MCP support** for attaching external tools like filesystem access and web search
- **Auto issue creation** so every Copilot run starts with a traceable GitHub issue

## 🚀 Quick Start

1. **Fork the repository** to your GitHub account or organization.
2. **Enable GitHub Copilot coding agent** for the fork.
3. **Add secrets** required by any MCP profile you plan to use, such as `BRAVE_API_KEY`.
4. **Open the Actions tab** and choose one of the dispatch workflows.
5. **Provide the workflow inputs** such as skill, agent, topic, or prompt.
6. **Review the auto-created issue and PR** generated by Copilot.

```bash
gh workflow run copilot-unified.yml \
  -f skill="Report Writing" \
  -f agent="Product Manager" \
  -f prompt="Draft an executive summary of MCP adoption options" \
  -f output_format=markdown
```

## 📋 Workflows

### 1. Unified Action (`copilot-unified.yml`)

This is the best default entry point when you want one workflow that can switch between skills, personas, output formats, and MCP profiles.

| Input | Description | Options / Examples |
| --- | --- | --- |
| `skill` | Skill definition the run should follow. | `Report Writing`, `PPT Generation` |
| `agent` | Persona used for expertise and tone. | `Default Copilot`, `AI Engineer`, `Backend Developer`, `Code Reviewer`, `Frontend Developer`, `Product Manager`, `Security Engineer`, `Software Architect` |
| `prompt` | Main user request sent to Copilot. | `Prepare a technical comparison of MCP servers` |
| `output_format` | Requested artifact format. | `markdown`, `html`, `pdf`, `pptx` |
| `mcp_profile` | MCP profile to activate for the run. | `none`, `filesystem`, `web-search`, `custom` |

**When to use it:** use the unified workflow when you want a single launch point for mixed tasks, want to choose an MCP profile at runtime, or want a simple self-service dispatcher for a broader team.

### 2. Report Writing (`report-writing.yml`)

This workflow creates an issue for a report-writing task and instructs Copilot to save the deliverable under `reports/`.

| Input | Description | Options / Examples |
| --- | --- | --- |
| `topic` | Report topic or title. | `Copilot rollout plan` |
| `agent` | Persona that shapes the report. | `Default Copilot`, `Product Manager`, `Software Architect`, `Security Engineer` |
| `report_type` | Report style to generate. | `Technical`, `Business`, `Research`, `Executive Summary`, `Competitive Analysis`, `Risk Assessment` |
| `format` | Final document format. | `markdown`, `html`, `pdf` |
| `depth` | Expected length and detail level. | `Brief (1-2 pages)`, `Standard (5-10 pages)`, `Detailed (10-20 pages)` |
| `additional_context` | Optional constraints or supporting context. | `Focus on regulated industries` |

**Example use cases**

- Executive summaries and quarterly updates
- Research briefs and competitive analysis
- Risk assessments, postmortem-style reports, and architecture narratives

> 💡 Tip: Use the Product Manager agent for executive-friendly reports.

### 3. PPT Generation (`ppt-generation.yml`)

This workflow creates an issue for presentation generation and instructs Copilot to produce both a `.pptx` file and a Markdown outline under `presentations/`.

| Input | Description | Options / Examples |
| --- | --- | --- |
| `topic` | Presentation topic or title. | `Enterprise MCP strategy` |
| `agent` | Persona driving deck structure and voice. | `Default Copilot`, `AI Engineer`, `Frontend Developer`, `Software Architect` |
| `presentation_type` | Deck style to generate. | `Technical Deep Dive`, `Executive Summary`, `Pitch Deck`, `Educational / Tutorial`, `Status Update`, `Competitive Analysis` |
| `slides_count` | Approximate deck length. | `5`, `10`, `15`, `20`, `25` |
| `audience` | Target audience. | `General`, `Technical`, `Executive / C-Suite`, `Investors`, `Customers` |
| `include_speaker_notes` | Adds speaker notes to each slide. | `true`, `false` |
| `additional_context` | Optional guidance or scope notes. | `Keep it investor-friendly and concise` |

**Example use cases**

- Technical deep-dive presentations for engineering teams
- Executive updates and board-ready summaries
- Sales, customer enablement, and tutorial-style decks

> 💡 Tip: Use the AI Engineer agent for technical deep-dive presentations.

### 4. Environment Setup (`copilot-setup-steps.yml`)

This workflow is called automatically by Copilot before task execution. It checks out the repository, installs Python 3.11, adds `python-pptx`, `markdown2`, `reportlab`, `pillow`, and `requests`, installs Pandoc, sets up Node.js 20 for MCP servers, and leaves commented hooks for optional MCP server installation.

### Selecting an agent in any workflow

- Use the workflow's `agent` input.
- Pick the persona that best matches the artifact and audience.
- `Default Copilot` is a safe starting point when no specialized persona is needed.

```yaml
with:
  agent: Software Architect
```

### Adding a new custom agent

Create `.github/copilot/agents/<name>.md` and define:

- the role and domain expertise
- when the agent should be selected
- preferred tone and output structure
- any linked skills or MCP tools

```text
.github/copilot/agents/data-analyst.md
```

## 🔧 MCP Configuration

MCP (Model Context Protocol) is the standard way to let Copilot talk to external tools.

### Activate a pre-built profile

1. Open a profile in `.github/copilot/mcp_profiles/`.
2. Copy its `mcpServers` entry into `.github/copilot/mcp_config.json`.
3. Remove the `_disabled` marker from the matching entry if you are enabling an example block.
4. Add required GitHub secrets.
5. Commit the updated config and rerun the workflow.

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/workspace"],
      "env": {}
    }
  }
}
```

### Add a custom MCP server

```json
{
  "mcpServers": {
    "my-custom-server": {
      "command": "npx",
      "args": ["-y", "@acme/mcp-server"],
      "env": {
        "API_KEY": "${MY_SERVER_API_KEY}"
      }
    }
  }
}
```

| Profile | Purpose | Requirements |
| --- | --- | --- |
| `filesystem` | Enables workspace read/write access for file-centric tasks. | None |
| `web-search` | Enables Brave Search-backed web research. | `BRAVE_API_KEY` |

## 🛠️ Adding New Skills

1. Create a skill definition file at `.github/copilot/skills/<skill-name>.md`.
2. Describe the skill purpose, trigger conditions, boundaries, and expected output.
3. Reference the skill from workflows or custom agent instructions.
4. Test a workflow run to confirm Copilot can discover and follow it.

```text
.github/copilot/skills/report-writing.md
```

A good skill definition usually includes:

- name and short description
- when to invoke the skill
- step-by-step execution guidance
- examples of successful inputs and outputs
